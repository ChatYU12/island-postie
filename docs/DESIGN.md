# 小岛邮差 · 玩法设计草案 v0.1

> 状态：讨论稿。方向已定：**散步跑腿为主（A），收集隐藏物品为辅（D）**。下面每节末尾的「待定」是需要一起拍板的问题。

## 一句话

你是小岛上新来的邮差。从星球降落到小岛，在十个地域之间送信、跑腿、认识居民，每帮完一片地方，就有新的路、桥或者地域向你打开。

## 参考游戏，以及借鉴什么

| 游戏 | 借鉴 | 不借鉴 |
|---|---|---|

## 我们已经有的东西

- **世界**：一颗星球和一片连续大陆，十个地域，十一条路线，六座桥，统一的高度场 `heightAt(x, z)`。
- **居民**：约 47 名居民沿安全路径行走，会互相让行；点击后镜头会跟随。
- **六个地点和六位主人**：项目协作馆（栗栗）、自动化邮局（豆豆）、数据观测台（澄澄）、客户服务站（阿杏）、知识图书馆（绵绵）、集成维修铺（阿栓）。名字来自原站的业务演示，要改成小岛上的生活场所。巧的是**自动化邮局**正好可以当主角的工作地点。
- **会动的设施**：风车、水车、钟楼、铁匠铺、喷泉、码头吊臂、炊烟。
- **天气和昼夜**：可以用作任务条件，比如「雨天才出现的蜗牛信」「夜里灯塔亮了才能出海」。
- **镜头**：固定的等距正交视角，可以缩放，能翻转 180°。

## 核心循环

```
在邮局领信 → 走去找收件人 → 对话，触发小委托 → 完成委托
      ↑                                        ↓
  新的信和地域 ←── 解锁新能力（过河、上山……） ←── 获得邮票或物品
```

- **单次时长**：一封信 1–3 分钟，一片地域 10–15 分钟，整岛通关约 1.5–2 小时。
- **没有失败**：不会死，没有计时惩罚，不会卡关。

## 操作（等距视角下）

- **点哪走哪**：点地面，邮差沿道路自动寻路走过去。手机和电脑上操作一样，最适合现在的固定视角。
- **点居民或建筑**：走到旁边，然后打开对话。
- **键盘**：WASD 或方向键直接走（相对于屏幕方向）；E 互动；R 翻转视角（已有）。
- 镜头跟随邮差，但保留拖动和缩放，可以看远处。

**待定 1**：只做点哪走哪，还是同时支持键盘直接操控？后者要处理碰撞，工作量大约翻倍。

## 收集要素（D）

- **遗失的邮票**：每个地域藏 5 枚，一共 50 枚。有的要拉近镜头才看得见，有的要在特定时间或天气才会出现。
- **明信片**：在风景点（栈道观景台、叠水、樱花林）停留时自动拍下，攒满一本相册。
- 菜单里有一本集邮册，显示每个地域的收集进度。

**待定 3**：邮票只是收集，还是可以拿来换东西（装饰邮局、给邮差换帽子）？

## 进度与存档

- 自动存到浏览器的 localStorage，不需要登录。
- 原站说过「不写浏览器存储」，那是营销站的承诺；游戏需要存档，会在设置里提供「清除存档」。

3. **第 2 步**：对话框和任务系统（数据驱动，任务写在 JSON 里），以及存档。
4. **第 3 步**：第一片地域的完整内容：3 封信、1 个委托、5 枚邮票，可以完整玩一遍。

先把第 1–3 步做成**可以玩的切片**再铺内容，这样手感不对能早发现。

## 已知的技术债

- 世界模块还是「挂在 window 上的脚本」，现在只是按顺序 import。以后新写的游戏代码用真正的 ES 模块，旧模块等需要改的时候再逐个转。
- 世界模块的名字和注释里还有原站的业务用语（`collaboration`、`automation`、「项目协作馆」等），会随着内容替换逐步改掉。
- 首屏一次加载约 2.8 MB 的 JS（gzip 后约 780 KB），其中模型数据占大头。等有了标题画面，可以把模型数据拆成单独的分包。
